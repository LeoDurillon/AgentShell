# copilot-agent

A minimal bash agent library for GitHub Copilot. Handles auth, streaming, tool calls, and conversation history — so you can build agentic scripts without boilerplate.

## How it works

```
chat.sh          → CLI entry point, manages conversation history
  └── run_agent.sh   → agentic loop: calls API, executes tools, loops until stop
        └── tools/call_tool.sh  → dispatches tool calls to individual scripts
              └── tools/function/*.sh  → one file per tool
```

The agent loop runs until the model either returns `finish_reason: stop` or calls a tool that signals completion. All conversation history is persisted to `conversations/<id>.json` between calls.

## Prerequisites

- `bash` 4+
- `curl`
- `jq`
- A GitHub Copilot subscription
- A session token in `copilot_token.json` (see [Authentication](#authentication))

## File structure

```
agent_sh/
├── chat.sh                  # Entry point
├── run_agent.sh             # Agentic loop
├── token_exchange.sh        # Auth flow
├── copilot_token.json       # Session token (generated by token_exchange.sh)
├── conversations/           # Persisted conversation history
└── tools/
    ├── tools.json           # Tool definitions sent to the API
    ├── call_tool.sh         # Tool dispatcher
    └── function/
        ├── edit_file.sh     # Apply file patches
        └── feature_complete.sh  # Signal task completion
```

## Authentication

Run the token exchange script once to authenticate via GitHub OAuth device flow:

```bash
./token_exchange.sh
```

This opens a browser auth flow using the VS Code Copilot client ID, saves a session token to `copilot_token.json`, and automatically refreshes it when expired.

The token expires after ~30 minutes. `run_agent.sh` checks expiry before each call and exits with an error if the token needs refreshing.

## Usage

### Start a new conversation

```bash
./chat.sh "<prompt>" [file1 file2 ...]
```

Prints the generated conversation ID to stdout. All subsequent output (model responses, tool activity) goes to `/dev/tty` directly.

```bash
# Simple prompt
./chat.sh "Explain this file" ./src/main.ts

# Multiple files as context
./chat.sh "Refactor the auth module" ./src/auth.ts ./src/types.ts
```

### Resume a conversation

```bash
./chat.sh --resume <conv_id> "<prompt>" [file1 file2 ...]
```

Loads the existing conversation history and appends the new prompt. Files are re-read from disk on every call so the model always sees the current file state.

```bash
CONV_ID=$(./chat.sh "Start task" ./src/lib.ts)
./chat.sh --resume "$CONV_ID" "Now add error handling" ./src/lib.ts
```

### List conversations

```bash
./chat.sh --list
```

### Delete a conversation

```bash
./chat.sh --delete <conv_id>
```

## Adding tools

### 1. Add the tool definition to `tools/tools.json`

```json
{
    "type": "function",
    "function": {
        "name": "my_tool",
        "description": "What this tool does",
        "parameters": {
            "type": "object",
            "properties": {
                "input": { "type": "string", "description": "..." }
            },
            "required": ["input"]
        }
    }
}
```

### 2. Create `tools/function/my_tool.sh`

The script receives the full JSON arguments as `$1` and must print its result to stdout. All logs go to `/dev/tty`.

```bash
#!/bin/bash
ARGS="$1"
INPUT=$(printf '%s' "$ARGS" | jq -r '.input')

echo "🔧 Running my_tool with: $INPUT" > /dev/tty

# Do the work
result=$(do_something "$INPUT")

# Return result to agent loop via stdout
echo "$result"
```

```bash
chmod +x tools/function/my_tool.sh
```

The dispatcher in `call_tool.sh` automatically picks up any script in `tools/function/` matching the tool name.

## Calling from another script

```bash
source ./config.sh   # SYSTEM_PROMPT, MODEL, ENDPOINT

# New conversation — stdout = conv_id
CONV_ID=$(./chat.sh "$PROMPT" "$FILE1" "$FILE2")

# Resume — stdout = last assistant message
RESPONSE=$(./chat.sh --resume "$CONV_ID" "$NEXT_PROMPT" "$FILE1")

if echo "$RESPONSE" | grep -q "feature_complete"; then
    echo "Done!"
    exit 0
fi
```

## Stdout contract

This is the key rule for composing scripts:

| Script | stdout | /dev/tty |
|---|---|---|
| `chat.sh` new conv | conv_id | logs, model output |
| `chat.sh --resume` | last assistant message | logs, model output |
| `run_agent.sh` | final messages JSON | logs, model output |
| `tools/function/*.sh` | tool result | logs |

**Never mix data and logs on stdout** — anything meant for the user goes to `/dev/tty`, anything meant for the calling script goes to stdout.

## Configuration

Edit `run_agent.sh` to change the model or endpoint:

```bash
MODEL="gpt-4o"                                        # any Copilot-supported model
ENDPOINT="https://api.individual.githubcopilot.com"   # or api.githubcopilot.com for business
```

Set `SYSTEM_PROMPT` before calling `chat.sh` — it is injected as the first `system` message in every new conversation:

```bash
export SYSTEM_PROMPT="You are a helpful assistant."
./chat.sh "Hello"
```

## Example: TDD agent

`tdd_agent.sh` is a reference implementation that uses this library to drive a Test-Driven Development loop:

```bash
./tdd_agent.sh <test_file> <implementation_file>
```

It starts a Copilot conversation, asks for one failing test, waits for the user to implement it, then loops until the feature is complete. See `tdd_agent.sh` for a full example of how to integrate `chat.sh` into a larger workflow.
